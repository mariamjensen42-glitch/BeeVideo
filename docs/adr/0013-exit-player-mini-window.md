# 退出播放页：退回 App 内 + 小窗，系统画中画只负责"离开 App"

## 背景

ADR-0012 把播放器搬进了 `PlaybackService`，于是"离开播放页"之后播放会继续。
但**屏幕上什么都不剩**：声音在响、看不到、也点不到。第一版按"离开页面音频继续"交付，
高城直接用一句话否掉 —— 「退出播放页面，还在播放，改一下这个，或者有个小窗口出来也合理啊」。

三个候选：

1. **退出即停播** —— 播放只在播放页里发生。最简单，但后台音频（ADR-0012 的一条验收口径）
   随之作废，锁屏与耳机键的控制也失去意义。
2. **系统画中画** —— 退出播放页就 `enterPictureInPictureMode`。
3. **应用内小窗 + 系统画中画分工** —— 返回键退回 App 内的上一页、画面转到自己画的悬浮窗；
   按 Home / 切 App 才走系统画中画。

## 决定

**3**，并且两条通路共用一个**用户开关**（`PlaybackSettings.pictureInPicture`，**默认关**）：

| 开关 | 返回键 | 按 Home / 切 App |
|---|---|---|
| 关（默认） | 退栈回 App 内的上一页 + 落进度 + **暂停** | 退到后台，声音继续（通知栏可控） |
| 开 | 退栈回 App 内的上一页 + **应用内小窗**继续放 | 缩成**系统小窗** |

两种情况下返回都**不会**退到手机桌面。

## 理由

**为什么 2 不行（这是唯一被实现过又拆掉的候选）**：系统画中画缩的是**整个 Activity**，
而按下返回那一刻 Activity 已经不在前台 —— 小窗背后就是**手机桌面**。
用户的感知不是"我离开了一个页面"，而是"**我被踢出 App 了**"。
一句话记住：**PiP 表达的是"离开 App 但仍看得见"，不是"离开这个页面"。**

**为什么是 3 而不是 1**：`PlaybackService` 已经是 App 级的（ADR-0012），
"停播"要在返回键上手写一次暂停，等于给一个本来就能活着的会话加一条特例；
而小窗只是把已有的画面换一个宿主，不动会话。代价是 UI 量，不是架构量。

**开关为什么管两条通路**：高城的口径从一开始就是
**「一般情况是退出播放页面就停止播放的，除非开了画中画」** —— 开关管的是
"退出播放页要不要继续放"。中途曾把开关挪去只管按 Home、返回一律出小窗，
下一轮就被打回来（"画中画，设置[里]关了，但是还在啊"）。
**开关 = 一个用户可解释的行为，不是一组实现的旁路。**

## 明确不做

- **可拖动 / 边缘吸附**：小窗固定在右下角。拖动要在浮层上再抢一层手势，
  与播放页自己那套（亮度/音量/进度/倍速）是同一类坑，收益只有"换个位置"。
- **小窗里放进度条与选集**：那块窗口按 16:9 算只有约 117dp 高，塞进去看不清也点不准。
  要跳集就点开播放页。
- **迷你条形态**（只有封面 + 文字 + 播放键、没有画面）：曾作为候选列出，
  高城选了"带画面的悬浮小窗" —— 小窗的意义就是别让画面消失。
- **返回键进系统画中画**：v1 的错，见上。

## 代价（知情）

- 内核**只有一个画面出口**：同一时刻只能有一个 `PlayerView` 绑着那个会话。
  于是小窗的显示条件里必须含"当前不在播放页"，而且从小窗回播放页要**先收小窗再导航**。
- 开关必须**当场生效**（播放页与小窗都挂着一个"退到后台自动进系统小窗"的开关）。
  它是全项目**唯一**做成 `StateFlow` 的设置项，理由与例外都写在同一处接口注释里。
- 开关从"开"拨到"关"时小窗会消失，但**播放不会自己停** ——
  必须在导航宿主补一句 `LaunchedEffect { pauseForExit() }`，否则又回到"画面没了、声音还在响"。
