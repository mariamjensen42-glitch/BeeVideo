# 站点长列表进弹层，日常切换落在首页顶栏

ADR-0005 把站点列表从横滑行改成换行网格，解决了"横着滑很久"，但没解决总量：
真机实测该配置 **86 个站点、每行只排得下 2 个 = 43 行**。铺在设置页里整页被它撑爆，
铺在首页同样如此。数量本身才是问题，换布局解决不了。

决定：

1. 站点列表搬进 `SourcePickerSheet` —— `ModalBottomSheet` + 搜索框 + `BeeChipGrid`。
   两处入口共用它：首页顶栏（日常切换）、设置页那一行（首次配置时找）。
2. 设置页那一行退化成"当前值 + 更换"，不再就地铺网格。
3. 首页顶栏副标题本来就在显示当前站点名 —— 把它改成可点 + `ArrowDropDown`。
   **这是"零额外步骤"的落点**：切站是高频动作，不能每次先跳设置。

## 为什么不是路由页面

高城的原话是"放在独立的页面，不过每一次切换就多了一步骤，不方便"。
跳转 → 选择 → 返回是三步；弹层是打开 → 选择，少了返回。所以用弹层。

代价是弹层里**没有返回键退出**（靠下滑或点遮罩），且盖住了顶栏 —— 而顶栏正好是入口。

## 为什么这里可以有搜索框（ADR-0005 的备选被反转）

ADR-0005 明确放弃了搜索，理由是"换站的常见情形是不知道有哪几个、想扫一眼"。
放进弹层后这条不再成立：**空白时铺全部**（照样能扫），输入才过滤 ——
两种情形各占一半，而不是二选一。

**没有做"最近使用"**：那要在 `PlaybackSettings` 之外再加一份持久化状态，
为省一步点击不划算。

## 代价与已知缺口

- ⚠️ 搜索只匹配 `name`（`contains`，忽略大小写），不匹配 id。
  实测输入 `jrs` → `共 1 个`，剩下的正是 `Jrs | 球迷`。
- ⚠️ 网格非懒加载：86 项一次全部组合测量。首帧在真机上没观察到卡顿，
  但这是**没量过的**，只是没看出问题。
- ⚠️ 用了 `skipPartiallyExpanded = true`：弹层直接展开到全高。站点多时这是对的，
  但站点只有两三个时，弹层仍是全高、下面一大片空白。
- 首页顶栏入口是**隐式**的：`Text` + `▾` 不带下划线、不是按钮外形，
  新用户不一定知道能点。当前判断是"比多占一行按钮值"，但这是个赌注。
