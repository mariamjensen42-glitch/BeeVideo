# 无痕模式：把"不记录"做成一道闸门，而不是逐页判断

## 背景

2026-09-29，高城要求：

> 无痕模式：开启后不记录播放历史。请说明该模式的开关机制、会话期间的临时数据处理方式、
> 退出时清除哪些数据，以及关闭后如何恢复正常的记录行为，并明确该功能的使用边界与注意事项。

三个语义分叉由他当场拍板，且**都选了最严格的一档**：

| 分叉 | 选择 |
|---|---|
| 之前正常模式攒下的历史 | **完全隐藏**（不是只读可见） |
| 无痕期间点收藏 | **按钮直接禁用** |
| 播放必然落盘的媒体分片 | **写独立目录，退出即删** |

于是这个模式的语义定为：**开启期间既不新增任何本地记录，也不显示任何已有记录**。

## 决定

### 1. 开关是一个进程内唯一的端口，不是页面的 `remember`

`domain/repository/IncognitoMode.kt`：`StateFlow<Boolean>` + `set(Boolean)`。
实现 `data/settings/PrefsIncognitoMode.kt`，单独一个 prefs 文件 `beevideo.incognito`。

- 用 `StateFlow`（同 `ThemeSettings`，而不是 `PlaybackSettings` 那种裸 get/set）：
  拨开关的在设置页，订阅它的在历史页、详情页、播放页与封面图里，**都不在同一棵子树**。
- 初值在构造时从 prefs 读出，订阅者第一帧就是对的。
- 由 `BeeApplication` 持有，**必须比 `library` 先建** —— 仓储的拦截要订阅它。
- ⚠️ **开关本身落盘，会话数据不落盘**。无痕是用户的选择，关掉 App 再打开仍然是无痕，
  直到他自己拨回去；而它产生的临时文件活不过一次会话。

### 2. 拦截点只有一处：`RoomLibraryRepository`

写方两个（进度上报、收藏切换），读方四个（历史页、首页「继续观看」、详情页的续播与收藏、
播放页的续播位置）。在页面里各判一次，漏掉任何一处都不会报错 —— 只会表现为"无痕了但某块还在记"。

- `saveProgress` / `toggleKeep` / `deleteProgress` / `clearProgress`：无痕时直接返回。
- `progressOf` 返回 `null`：**续播也不给**。把一条旧记录的位置带进来，正是这个模式要藏的东西。
- `progressList` / `keeps` / `isKept`：用 `combine(dao 那条流, incognito.enabled)` 把开关并进来。
  于是"打开 → 列表立刻变空；关掉 → 原样回来"由同一条流保证，界面不用写任何分支。

⚠️ `saveProgress` 的拦截必须排在**节流闸门之前**：放到之后的话，被丢弃的那次调用仍会刷新
`ProgressWriteGate` 的时间戳，表现为"关了无痕，前 5 秒的进度还是没记上"。

### 3. 媒体缓存走独立目录，退出时整目录删除

`MediaCacheProvider` 从"全进程一个单例"改成**按目录名分桶**（`media` / `media-incognito`）——
`SimpleCache` 对同目录加文件锁，不同目录各建一个实例是安全的。

为什么不是"干脆不缓存"：点播源的媒体没有断点续传语义，禁写缓存等于每次拖动进度条都从头拉一遍。
独立目录让**零残留**与**拖得动**同时成立，而且退出时只需删一个目录，不必按时间挑文件。

### 4. 封面只进内存缓存

`BeePosterImage` 通过 `LocalIncognito`（CompositionLocal）读会话状态，无痕时给请求加
`diskCachePolicy(DISABLED)`。Coil 的磁盘缓存**没有按时间挑选的接口** —— 进了盘就只能整份清掉，
那会连用户正常模式攒下的封面一起清。

退出无痕时清一次 Coil 的**内存**缓存（`BeeApplication.coverLoader`）。为此 `newImageLoader()`
返回一个字段而不是每次现建：现建一个只会清到一个没人用过的实例。

### 5. 退出的收尾在 `PrefsIncognitoMode.set(false)` 里触发

`onExit` 回调由 `BeeApplication` 组装，两件事都在后台线程（删目录要遍历上千个分片文件）：

- `MediaCacheProvider.clearIncognito(app)`：释放无痕缓存实例 + 删目录。
- `coverLoader.memoryCache?.clear()`。

⚠️ 与 `MediaCacheProvider.clear()` 同一条约束：**调用前不能有播放器在放**（release 掉实例会让
正在读它的 `CacheDataSource` use-after-release）。这里成立，因为无痕开关只在设置页，而播放页在
另一条栈上 —— 要够得着设置页必须先退出播放。

### 6. 界面三处

- 设置页新增【无痕模式】一节（开关 + 说明 + 开启时的补充提示），紧挨在「播放缓存」之后 ——
  两者最容易混（都跟"本机留下什么"有关），挨着才好对照"缓存不受影响"那句话。
- 历史页：`HistoryUiState.incognito` 让空态换成"无痕模式已开启"。同样是空列表，
  「还没有观看记录」是在说**用户没看过**，那是另一件事。
- 详情页：`keepEnabled` 只决定按钮灰不灰。写入早就被仓储拦掉了，这个标志管的是
  "让用户看得出按不动" —— 一个点了没反应的按钮比一个灰掉的按钮更让人困惑。

## 代价与风险

- ⚠️ **"完全隐藏"会让历史页突然变空**。用户若忘了自己开着无痕，会以为记录丢了。
  缓解是历史页那句文案（"关掉无痕模式就都回来了"），但**它只在用户进这一页时才看得到**。
- ⚠️ **进程被杀时无痕目录会残留**。收尾挂在"拨开关"这个动作上，没有启动时兜底清理。
  下次开 App 如果无痕还开着，那份残留不会被删（但也不会被读 —— 目录名不同）。
  真要兜底得在启动时判"无痕开着且目录非空则删"，本轮没做，因为**残留的只是可再生缓存**。
- ⚠️ **不是安全边界**：它挡的是"本机留下记录"，不挡网络侧（源站、CDN、DNS 全都看得见）。
  也不隐藏 IP，这一点必须在文案里说清楚 —— 用户对"无痕"的常见误解正在这里。
- ⚠️ 无痕与"播放缓存"是两个独立偏好：无痕下缓存**仍然开**（只是写到另一个目录），
  用户把缓存开关关掉时无痕也不缓存。两者相乘，不是覆盖。
- **可撤销**：删掉 `IncognitoMode` 的注入与三处界面即回到原状态，没有数据迁移。

## 没做的

- **搜索历史**：现状就不记录搜索词（`SearchState` 只有 `input` / `submitted`，不落库），
  所以无痕在这一块无事可做 —— 不是遗漏。
- **启动时兜底清理**：见上，残留物是可再生缓存，成本大于收益。
- **无痕会话的独立进度**：不记录就是不记录，没有"无痕里也能续播、关掉再清"这一档。
