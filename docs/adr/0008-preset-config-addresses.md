# 在设置页预置配置地址（**推翻原红线**）

## 背景

项目原来的第一条红线是「**不内置 / 不推荐 / 不分发内容源**」—— 界面文案
（`settings_source_body`）与 ADR 里都是这么写的，产品定位是纯粹的"播放器外壳"：
内容源由用户自持，App 只负责播放。

2026-09-27，高城在拿到一份"体检过的可用地址清单"之后要求：

> 这些地址都要作为配置地址的，方便用户切换

明确选择了「**预置这几条**」，即接受破线。

## 决定

1. 新增 `ui/settings/RecommendedConfigs.kt`：5 条 `RecommendedConfig`（名字 + 说明 + url）。
2. 设置页「内容源」一节在**输入框之上**加一组 `BeeChipGrid`，点击即切换
   （`state.applyConfig(url)`）；同时把地址回填进输入框 —— 否则切完输入框还留着旧地址，
   看着像没生效。
3. 选中态判据是 `status.configUrl`（**已生效**的），不是输入框里的字。
   地址敲进去但还没点「装载」时 chip 不该先亮 —— 那是在暗示已经生效。
   用户自持的地址不匹配任何一条时下标为 -1，整组不选中。
4. `settings_source_body` 文案改掉"不内置、不推荐、不分发"那半句，但**保留免责**：
   内容源由第三方提供、只做播放、不生产不运营不保证可用。

## 为什么这几条

全部来自 `probe_config.py` 的体检（详见 `REFERENCE.md`「内容源 / 配置地址体检」）：

| 名字 | 地址 | 体检 |
|---|---|---|
| 推荐 | `qist/…/fty.json` | 47 站 / 43-44 命中 / **真机端到端跑通**（糯米，首页 12 部 + 海报） |
| 大合集 | `qist/…/0825.json` | 135 站 / 100-106 命中 / jar 加载执行成功 |
| 站点最多 | `liu673cn/box/…/m.json` | 234 站 / 146-165 命中 |
| 网盘 | `qist/…/9918.json` | 56 站 / 24-24 全命中 |
| 备用 | `gao/…/0821.json` | 86 站 / 38-38 全命中 |

**每条都必须带 `https://ghfast.top/` 镜像前缀**。配置里的 jar 是相对路径
（`"spider": "./jar/fan.txt;md5;…"`），会跟着配置地址解析；少了前缀就落到
`cdn.jsdelivr.net`，而 jsdelivr 对 `*.jar` **全节点 403**（响应体 9 字节）
→ **每个 `csp_` 源都报「下载 jar 失败」**，看着像 App 坏了。

⚠️ **`qist/dianshi.json` / `jsm.json` 不要加回来**：它们数字最漂亮（151 / 150 站、
103 个 `csp_` 全命中），但 `spider.jar`（4.8MB dex）会让 App **直接 native 崩** ——
无 Java `FATAL`、无 `am_crash`/`am_anr`，只有一条 `am_proc_died`，真机必现。

## 代价与风险

- ⚠️ **法律暴露面变了**：仓库是**公开 + GPL-3.0**，预置的地址会随 APK 一起分发。
  「用户自持地址」和「App 推荐地址」在定性上是两件事。
  这条是破线的**核心成本**，不是技术问题。
- ⚠️ **地址会失效**：这些都是第三方仓库，随时可能改名 / 删库 / 换 jar。
  预置项一旦失效，"推荐"那个 chip 会直接把用户带进失败态。
  ⇒ **每次动这批地址前先跑 `probe_config.py`**，别无脑加。
- ⚠️ 预置列表是**编译进 APK 的常量**，改它要发新版。真要做成"可远程更新"，
  那是另一件事（也把风险抬高一级），本轮不做。
- **可撤销**：删掉 `RECOMMENDED_CONFIGS` 里的条目（或整个文件 + 设置页那段 UI）
  即回到原状态，没有数据迁移。

## 没做的

- 没做"用户自存多份地址"的地址簿。高城这次要的是**预置 + 一键切换**；
  地址簿是另一个特性，需要动 `SourceStore` 的持久化格式，本轮不夹带。
