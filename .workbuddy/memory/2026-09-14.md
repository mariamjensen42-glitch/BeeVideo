## 勘误：参考项目章节重写（同日）

**我犯的错**：用 Glob 工具判断 `D:\Programming\Kotlin\TV-Multiplatform-main` 是否存在，
Glob 返回空就下了"不存在"的结论。高城指出"肯定存在"，用 Python `os.path.isdir` 实测——

**实测得到的真实情况**（v1.2.5，已在 `docs/scope-and-m1-delivery.md` 第 1 节重写）：

- 模块只有 `:composeApp` 和 `:Web-Player`，`composeApp` **只声明 `jvm("desktop")`，没有 Android target**。
- 播放层用 **vlcj 4.12.1（VLC）**，不是 Media3/ExoPlayer，桌面专属。
- 115 个 Kotlin 文件，包名 `com.corner`：
  - `catvodcore/` —— CatVod 体系的 Kotlin 重写（bean 含 Vod/Site/Api/Rule/Parse/Episode/Flag/Filter 等），
    `loader/JarLoader` 动态加载 Java 爬虫，`util/` 含 Http/Jsons/ProxySelect。
  - `github.catvod/` —— CatVod 原始包名，crawler/Spider、net/OkHttp。
  - `database/` —— Room，四张表 Config / History / Keep / Site。
  - `ui/nav/` —— 五个 ScreenState + 五个 ViewModel，页面为首页/搜索/历史/设置/详情。
  - `dlna/` jupnp、`server/` Ktor 内嵌 HTTP、`util/play/` 外部播放器调用（VLC/MPC/Potplayer）。
- 另有 `Web-Player/`（Vite + React + TS）和 `Updater/`（Go）。
- LICENSE 为 GPLv3 全文（35,149 字节），确认 GPL-3.0。

**结论修正**：TV-Multiplatform 提供不了安卓播放层，但提供了一整套 Kotlin 化的
**内容源层**与 **UI 组织方式**——这恰好是 BeeVideo 最缺的部分。

**顺带解决的一个坑**：原计划"FFmpeg 软解 AAR 需自编"，可改用安卓端
`org.videolan.android:libvlc-all`，与 vlcj 同源且自带全格式解码。

## 页面骨架与组件槽位化（同日）

### 第一版骨架（不灵活）

抽出 `BeePage` / `BeeTopBar` / `BeeChipRow` / `SectionTitle` / `BeeEmptyState`，
三个页面切过去。编译、装机、链路都正常。

**高城指出问题**：`BeeTopBar(title: String, onBack: ...)` 把标题写死成字符串、
返回写死成文字按钮，想自定义（图标返回、双行标题、头像）无路可走。
等于把一个不灵活的抽象推广到了全项目。

### 修正为槽位（slot）设计

| 组件 | 槽位 |
|---|---|
| `BeePage` | `topBar` 可换可空；另有 `title/onBack/actions` 便利重载 |
| `BeeTopBar` | `navigation` / `title` / `actions` 三槽位全可替换 |
| `BeeTopBarDefaults` | `BackButton`（文字）/ `BackIcon`（图标）/ `Title`，可作自定义起点 |
| `SectionTitle` / `BeeEmptyState` | slot 版 + 纯文本便利重载 |
| `BeeChipRow<T>` | 泛型，`label` 决定每一项外观 |

**踩坑**：`navigation = onBack?.let { { ... } }` 的 Composable lambda 类型推断不可靠，
写成 `if (onBack == null) null else { { ... } }` 后编译通过。

**教训**：抽公共组件时，**内容一律走槽位**，只有最表层给便利重载。
凡是把"标题""标签"定成 `String` 的参数，迟早会挡路。

验证：BUILD SUCCESSFUL（41s）；真机安装后 首页 → 详情 → 播放 全链路正常，无崩溃。

## M3 Expressive 落地（同日）

### 关键事实：1.4.0 稳定版没有公开的 Expressive API

Context7 给出的 Expressive 文档来自 **1.5.0-alpha**。实测探针证明，
BOM 2026.06.01 指定的 **material3 1.4.0** 中下列 API 全部为 `internal` 或根本不存在：

`MaterialExpressiveTheme` / `MotionScheme` / `ExperimentalMaterial3ExpressiveApi` /
`LoadingIndicator` / `MaterialShapes` / `Shapes(largeIncreased…)` / `TopAppBar(subtitle)`

**解决**：在 `libs.versions.toml` 里显式指定 `material3 = "1.5.0-alpha28"` 覆盖 BOM。

**1.5.0-alpha28 实测可用**：`MaterialExpressiveTheme`、`MotionScheme.expressive()`、
`Shapes` 八个槽位（含 largeIncreased / extraLargeIncreased / extraExtraLarge）、
`TopAppBar(subtitle)`、`LoadingIndicator`、`CircularWavyProgressIndicator`、
`LinearWavyProgressIndicator`、`ToggleButton`、`MaterialShapes.Cookie9Sided / Clover4Leaf / PuffyDiamond`、
`ButtonGroup`（签名需 `overflowIndicator` 参数）。

**仍不可用**：`expressiveDarkColorScheme`、`IconButtonDefaults.mediumShape`。

### 第一次尝试失败（重要教训）

只换了主题外壳 —— `MaterialExpressiveTheme` + `MotionScheme.expressive()` + 放大圆角 `Shapes`，
**观感几乎没变化**。高城直接指出「跟官方差别很多」。

原因：Expressive 的「明显」来自 **排版跨度** 与 **组件形态**，不是主题配置。
主题只影响默认色与默认形状，而我用的组件全是标准 M3 基础款。

## Expressive 第二轮：连接式按钮组 + LoadingIndicator（同日）

高城要求继续。摸清了官方的真实做法（Context7，material3 参考文档）：

**关键 —— 「连接式按钮组」不是用 `ButtonGroup`，而是 `FlowRow`/`LazyRow` + `ToggleButton` 配一组连接形状：**

```kotlin
shapes = when {
    index == 0                -> ButtonGroupDefaults.connectedLeadingButtonShapes()
    index == items.lastIndex  -> ButtonGroupDefaults.connectedTrailingButtonShapes()
    else                      -> ButtonGroupDefaults.connectedMiddleButtonShapes()
}
horizontalArrangement = Arrangement.spacedBy(ButtonGroupDefaults.ConnectedSpaceBetween)
```

`ButtonGroup` 本身签名是
`ButtonGroup(overflowIndicator: @Composable (ButtonGroupMenuState) -> Unit, modifier, expandedRatio, horizontalArrangement, verticalAlignment, content: ButtonGroupScope.() -> Unit)`，
必须提供溢出入口，用在固定分类上不方便，故未采用。

**改动**：

| 位置 | 内容 |
|---|---|
| `BeeChipRow` | 改为按位置套用 connectedLeading/Middle/Trailing 形状 + `ConnectedSpaceBetween` 间距，整排拼成连续胶囊 |
| `PlayerScreen` | 加 `isBuffering` 状态（`Player.Listener.onPlaybackStateChanged`），缓冲时在画面中央叠加 `LoadingIndicator`；`DisposableEffect` 合并了 listener 注销与 player 释放 |

**踩坑**：`LoadingIndicator` 需要 `@OptIn(ExperimentalMaterial3ExpressiveApi::class)`，
且该注解必须加在**直接调用它的函数**上（`PlayerScreen`），只加在 `PlayerScaffold` 上不够。

**环境问题（连续踩两次）**：截图得到 15KB 纯色图 —— 不是崩溃，
而是 `mWakefulness=Asleep`，**设备自动熄屏**。
需 `input keyevent KEYCODE_WAKEUP` 唤醒；但设备有锁屏密码，
唤醒后停在锁屏，**ADB 无法解锁，必须由用户手动解锁**。
排查结论：`dumpsys activity activities` 有 `mFocusedApp`、logcat 无 FATAL，即可排除崩溃。
用户解锁后补截成功（`KEYCODE_WAKEUP` + `am start`，760KB）。

**真机验证（全部生效）**：

| 截图 | 验证到的 Expressive 特性 |
|---|---|
| `20-bg-home.png` | 分类栏整排拼成**连续胶囊**（leading 大圆角 + 中间方角 + trailing 大圆角），按钮间无缝隙；`headlineMedium` 大字标题 |
| `21-bg-detail.png` | 顶栏副标题「8.6 分 · 2024」；线路选择为 leading+trailing 连接胶囊；片名 `headlineSmall` |
