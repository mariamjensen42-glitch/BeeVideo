## 设置页站点选择：横向滚动行 → 换行网格

**起因**：高城反馈「设置页面的视频源切换不方便，是横向滚动的」。

高城直接拍板「直接网格显示全部，不用滑动」，没按建议的"搜索 + 列表"走。

**改动**：
- 新增 `ui/components/BeeChipRow.kt` 里的 `BeeChipGrid<T>`：`FlowRow` 换行网格。
  照抄 M3 官方 `SingleSelectConnectedButtonGroupWithFlowLayoutSample` 的写法 ——
  连接式形状按**全局下标**算（首项 leading、末项 trailing、其余 middle），
  官方写死 `verticalArrangement` 2dp，这里改引 `ButtonGroupDefaults.ConnectedSpaceBetween`（就是 2dp）。
- 顺带把行与网格共用的形状 `when` 提成 `connectedButtonShapes(index, count)`，
  免得两处 `when` 分叉（原来 `BeeChipRow` 里内联的那份逻辑一字未改地搬了过去）。

  原因：原来两稿都是 3 个等长名字，网格和横滑行长得一模一样，等于没预览。

**查证过的事实**（不是猜的）：

- 设置页整页 `Column + verticalScroll` → 里面**不能**放 `LazyVerticalGrid`（无限高约束抛异常），
  只能非懒的 `FlowRow`。
- 查证手法：Gradle 缓存里有 `*-sources.jar` 就直接读 Kotlin 源码，比查网页准；
  只有 pom/module 缓存没有 aar 时，去找同 group 下别的版本。

## 续：所有 `.js` 源集体报错 → 宿主补 `pdfh`/`pdfa`/`pd`/`pdfl`

**高城原话**：「js都报错，解决这个问题」。

**真机报错原文**（`uiautomator dump` 从界面读出来，logcat 里当时没有这条）：
```
读取失败：站点「动漫┃NT动漫[js]」初始化失败：
QuickJSException: UnhandledPromiseRejectionException: 'pdfh' is not defined
  at https://cdn.jsdelivr.net/gh/qist/tvbox@master/lib/drpy2.min.js:1059
```

**根因**：drpy2 **模块顶层**就写 `const defaultParser = { pdfh: pdfh, pdfa: pdfa, pd: pd }` ——
求值那一刻引用的是**裸全局名**。宿主从来没注册过这四个函数
→ 所有走 drpy2 的 `.js` 源在 init 阶段**一起**报废（该配置 86 站点里 37 个 `.js`）。

**定位过程（都是实测，不是推断）**：
1. logcat 全空（日志 buffer 太小）→ 改 `uiautomator dump` 读界面上的错误全文；
2. 从设备拉配置（86 站点 / 37 个 `.js`）；
3. 在 `createFun()` 补日志重装 → 拿到
   `ClassNotFoundException: Didn't find class "com.github.catvod.js.Function" on path: DexPathList[[zip file "…/8432d174….jar"]]`
   —— 参考宿主（FongMi）的 `pdfh` 就是从这个类来的；
4. 下载 `jar/fan.txt`（1113588 字节，md5 与本地一致）确认是 **fty 加固**：
   `classes.dex` 只有 36852 字节、带 `assets/ftyguard_v*.so` + `assets/ftyshinidie.guard`，
   DEX 里 `pdfh` / `js/Function` / `org/jsoup` **全部为 0**；
5. 全盘搜本地 `TV-fongmi` 仓库也没有该类所在的 jar
   → **「换一个带 `Function` 的 jar」这条路走不通**。

**修复**：宿主自己实现（ADR-0007）。
- 新增 `data/source/vod/js/DomParser.kt`，逐行翻译参考的 `com.github.catvod.js.utils.Parser`
  （三个正则、`:eq(0)` 补全、`--` 排除、单槽 Document 缓存、`style` 抠 URL、`UriUtil.resolve` 拼 base）。
  底座改用 **jsoup 1.21.1**（新依赖，`libs.versions.toml` + `app/build.gradle.kts`）。
- `JsSpider.createFun()` 改成**先注册宿主实现、再用 jar 覆盖**，且**不再吞掉失败原因**：
  ```
  I/QuickJS: jar 无 com.github.catvod.js.Function，继续用宿主内置实现（ClassNotFoundException）
  ```
- ⚠️ 注册必须在 `createObj()` **之前**；`pdfl` 不能省（drpy2 用 `typeof pdfl === "function"`
  判断自己在跑 drpy2 还是 drpy2.1，缺了是**静默降级**）。

## 附：顺手核出来的两条「另一类问题」（不是本次 pdfh 的锅）

**① csp_ 源报「jar 里找不到类」** —— 切到 `🐟白白┃秒播`（`csp_SbaibaiGuard`）时界面红字：
```
读取失败：jar 里找不到类 com.github.catvod.spider.SbaibaiGuard。
检查配置的 api 字段（应是 csp_ 加类名）与该 jar 是否匹配。
```
- 同一份 jar 下 `糯米`（`csp_NmyswvGuard`）**是好的** → 不是 loader 坏，是**这个 jar 里没有那个类**。
- 设备上的 jar 是 `files/catvod/jar/8432d174….jar`（1113588 字节，= 配置的 `./jar/fan.txt`），
  入口只有 `classes.dex` + `assets/ftyguard_v{7,8}.so` + `assets/ftyshinidie.guard`。
  ⚠️ **`classes.dex` 解不出来**：`zipfile` 读出来是 `Bad magic number for file header`
  —— fty 加固，类名是运行时由 native 解密的，静态数不出「到底有几个 Guard 类」。
- 结论：那一批 `csp_*Guard` 源**有几个能用取决于那份 jar**，不是 App 的 bug。
  想判定某个 csp_ 源是否可用只能**逐个切过去试**。

**② JS 源的海报占位** —— `drpy_js_网易公版影像` 的 `vod_pic` 是**明文 http**
（`http://cms-bucket.ws.126.net/...`），设备上取不到 → 海报全是渐变占位（标题/分类照常）。
- 已排除「App 不支持 http 图片」：`network_security_config.xml` 是 `cleartextTrafficPermitted="true"`，
  且同一台机上糯米（https 图）海报全部正常加载；那个 http 源的实际播放地址
  （`http://flv0.bn.netease.com/...`）也能播 → 明文没被拦。
- ⚠️ 宿主机上同一个图片 URL 返回 200 / 1MB，但**宿主机那条链路走了代理**，
  不能代表设备的网络 → **判定「源站挂了」不能只看宿主机能不能取到**。

（`CatVodConfig.kt:214` 的 `URI(base).resolve(ref)`），于是**每个 `csp_` 源都报「下载 jar 失败」**。

真机原文：
```
读取失败：下载 jar 失败：https://cdn.jsdelivr.net/gh/qist/tvbox@master/jar/spider.jar（HTTP 403）
```

**解法：配置地址加镜像前缀。** 实测 `ghfast.top` / `gh-proxy.com` / `ghproxy.net` 都行
（`gh-proxy.net` 429；`gh.llkk.cc` / `ghproxy.cc` / `hub.gitmirror.com` / `statically.io` 连不上）。
`URI.resolve` 会让 `./jar/fan.txt` 自动拼到镜像后面，**配置 + jar 一起走镜像**。

已把这条写进 `install_debug.py` 的 `DEFAULT_CONFIG` 注释里（默认值也换成了镜像地址）。

### 2. 「jar 里找不到类」里有一半，换个配置就能修

与 CDN 上实际内容不符时，会拿着旧名字加载新 dex。

  后者正是同作者 **`fty.json` 声明的那份**。⇒ `fty.json` 就是「修好版」。
- 实测 `0821.json` 42 个 `csp_` 里 **13 个类找不到**（缺 `AList,AppSKGuard,DdrkGuard,
  LiteAppleGuard,MIPanSoGuard,PanSearchGuard` 等）；`fty.json` 只缺 1 个（`XPathGuard`）。

⚠️ 但**「白白」(`csp_SbaibaiGuard`) 不属于这类** —— `qist/tvbox` 的 `fan.txt`
**30 个历史版本里都没有这个类**（`_fanscan` 扫过），换配置也修不掉，只能换个源。

⚠️ 顺带**纠正一条旧结论**：之前记的「fty 加固的 `classes.dex` 解不开（`Bad magic number`）、

## 续六：播放器第一版 · 第 2 步「手势 + 横屏全屏」落地(代码完成，未上机)

  - `dragToPositionMs`：**时长未知（0）时返回原位，不返回 0**。时长未知是常态
    （来源没给时长），跳回开头是纯粹的惊吓。

## 续八：第 3 步 —— 线路切换 + 自动下一集（已上机验证）

### ⑩ 自动下一集：卡在「状态」和「转移」的区别上

- `STATE_ENDED` 原本被并进 `Idle`，于是"播完了"和"还没起播"是同一种状态 ——
  自动下一集**在状态层面根本无从判断**（界面只能靠 `当前位置 == 时长` 去猜，
  而来源不给时长时那是 0）。→ 新增 `PlaybackState.Ended`，`Media3PlaybackSession`
  单独映射 `Player.STATE_ENDED`。
- ⚠️ **第一版实现写在播放页里，是错的**：以"当前状态是不是 Ended"来推，
  而 `Ended` 会**一直持续到新集起播**（`playState` 取地址要一次网络往返，
  这中间状态一直是 Ended）→ 每重组一次就再跳一集，一口气跳完整季。
  改成以"算出来的目标集号"为 key 也一样会连跳（跳过去之后目标变成 +1，仍是 Ended）。
- **定案：判据搬进持有者，按状态*转移*触发**，并记住"这一集已经处理过"
  （`advancedForEpisode`），**离开 Ended 才重新武装**。收益：
  ① 单元测试第一次能直接断言"播完 → 集号 +1 且先落库"；
  ② 跨 Activity 重建存活（播放页里的 `remember` 不存活）。
  判据本身抽成纯函数 `autoNextEpisode(state, index, count, enabled)`。
- 最后一集播完**也要落一次库**：周期上报只在"在播"时跑，片尾那不到一秒的位置
  否则永远比实际差一截。
- 开关 `PlaybackSettings.autoPlayNext`（默认开）+ 设置页新增「播放」节，
  与缓存配额同样**进页面读一次**。

### ⑧ 线路切换：`lineIndex` 是导航参数，不能当状态用

## 全屏切换「先竖后横」+ 不丝滑 —— 三处修复

高城反馈：切全屏时画面先按竖屏显示一下，然后才横过来；整个过程不丝滑。

**根因**：进全屏时两件事各走各的时间线。
1. `isFullscreen = true` → Compose **立刻**切全屏分支（画面 `fillMaxSize`），但窗口还是竖的
   1080×2400，Media3 默认 `RESIZE_MODE_FIT` 把视频缩成中间一条 → 这就是"先竖着"。
2. `requestedOrientation` 是**异步**的（经系统服务，几百毫秒），转完才铺满 → "然后横屏"。

另外 `configChanges` 含 `orientation|screenSize` → Activity 不重建 → 系统**不播转屏过渡
动画**（那动画只在重建路径上才有），所以本来就只有一次硬 relayout，谈不上平滑。

**修的**（`PlayerScreen.kt` / `PlayerFullscreen.kt`）：

1. **渲染判据改成真实方向，不是点击意图。**
   `fullscreenIntent`（`rememberSaveable`，点击态）只驱动 `requestedOrientation`、返回键、
   全屏按钮图标；布局用 `LocalConfiguration.current.orientation == LANDSCAPE`。
   布局切换与系统转屏同帧发生 → 中间态消失。
2. **全屏与竖屏共用同一棵树。** 原来是 `if (isFullscreen) { Box{player()}; return }`，
   两棵子树 → 切进切出时画面槽父容器整个换掉，`AndroidView` 被 dispose 再新建，
   `SurfaceView` 跟着 detach/attach，surface 销毁重建 = **黑闪一帧**。
   现在只改画面槽自己的 modifier，差别只剩三处：顶栏在不在、要不要滚动、画面槽多大。
   ⚠️ 全屏时 `contentWindowInsets` 要显式给 0，且**不能挂 `verticalScroll`**（会把
   `fillMaxSize` 丢进无穷高度约束，画面撑不开）。
3. **退全屏时系统栏延迟到真转回竖屏再 `show`。** 跟请求方向放一起的话，横屏下会先冒出
   状态栏、画面缩一下，然后才转屏 —— 又一次多余跳变。进全屏则相反，`hide` 要和请求方向
   **同时**做（竖屏下那次尺寸变化被转屏吃掉）。
