## 性能优化（"尽你所能"）
按收益顺序做了 7 项：
1. **新增 `app/compose-stability.conf`** + `build.gradle.kts` 的 `composeCompiler { stabilityConfigurationFiles }`：
   把 `domain.model.*` 声明为 stable。核对（重跑编译器报告）：`Vod` 由 unstable → **stable**，
   `PosterCard(vod)` 从 `unstable vod` → **`stable vod` + `stable onClick`**（lambda 终于能被记住）。
2. **`contentType`**：首页网格（row/poster/footer）、详情网格（info/lines/episode）、搜索网格（row/poster）。
3. **翻页状态读取点下移**：`state.more` 从 HomeFeed 顶层挪进 footer 的 item 内 —— 翻页状态变化只重组那一项。
4. **补 key**：`DetailBody` 剧集网格、`PlayerScaffold` 选集，都用 `"$index:$name"`（只用集名会在重名时撞 key 崩溃）。
   `BeeChipRow` **不加** —— 泛型 T 没有可靠 key 来源，chip 少且顺序固定。
5. **Coil 全局 `ImageLoader`**（`BeeApplication` 实现 `ImageLoaderFactory`）：`respectCacheHeaders(false)`
   —— 图床发 `no-cache` 时 Coil 默认跳过磁盘缓存，等于每次滚回来重下。
6. **`BeePosterImage`**：`remember(pic)` → `remember(pic, context)`。
7. **`PosterCard`**：`posterBrush(id)` 加 `remember`（要算两个 hsl 颜色，不必每次重组重算）。

**没做**：手动预取下一屏 —— Coil 的 disk cache key 含 size，预取的尺寸和后端解析出的尺寸对不上就会
存成两份、白下载，收益为负（Lazy 本身已有内置预取）。

验证：单测 305 全绿；装机走通 首页 → 详情（23 集网格）→ 播放（选集 01-06）无 FATAL
（logcat 里那条 FATAL 是 `uiautomator dump` 自己崩的，不是 App）。

## 更正：稳定性配置的**理由**写错了（强跳过模式）
查证（Kotlin 官方文档 + 多个来源）：**强跳过模式自 Kotlin 2.0.20 起默认开启**，本项目 Kotlin 2.2.10
= 一直是开的。于是 `compose-stability.conf` 头部原有的两条理由**都不成立**：
- ❌「unstable 让跳过检查退化成 `equals` 深比较」—— 强跳过下 unstable 参数按**引用** `===` 比较，
  深比较是强跳过之前的老行为，方向正好相反；
- ❌「捕获 unstable 值的 lambda 无法被 memoize」—— 强跳过会把捕获 lambda 包进 `remember(captures)`。

真实收益：声明 stable 后，参数比较从 `===` 换成 `equals()` —— 列表重新解析出一批**内容相同的新
`Vod` 实例**时仍能跳过（不声明就每次都重组那一卡）。已改 `compose-stability.conf` 头部注释与
`app/build.gradle.kts` 里那段注释（顺手按「注释精简」压短）。
