## CatVod 兼容层：照 `FongMi/TV` 权威源码重译，并把 ABI 钉死

起因：`FongMi/TV` 才是 Java 版空壳的**原始实现**，`com.github.catvod.*` 应当照它翻译，
而不是从下游衍生版推测。

### 怎么拿到权威源码
`raw.githubusercontent.com` 直连会断连，走 `gh api repos/FongMi/TV/contents/<path>?ref=fongmi`
拿 base64 再解码（脚本 `fetch_fongmi.py`，`--list <prefix>` 查 `tree.json`）。
⚠️ **默认分支是 `fongmi` 不是 `main`** —— 用 `main` 拿不到 tree。
❗抽出来的是 **GPL-3.0** 源码，只作行为规格读，**用完即删**（本轮已删 `_fongmi/`）。

### 读源码 + 实测 jar 后改掉的 8 处
| 问题 | 依据 |
|---|---|
| `client()`/`safeDns()` 写成**实例方法** | 实测 `invoke-static` —— **本来永远不可能工作**，纯静默 bug |
| 方法名写成 `proxyLocal` | 权威是 `proxy(Map)` → 覆写根本没生效 |
| 搜索第一页调了**三参版** | 权威 `hasPage = !page.equals("1")`，第一页走**两参版** |
| 漏了 `homeVideoContent()` 的调用与合并 | 权威调**两次**，非空则 `result.setList(...)` 覆盖 |
| 漏了 `siteKey = key` **先于** `init` | `JarLoader.getSpider` 的顺序 |
| 缺 `SpiderApi` / `Notify` 两个宿主类 | jar 会引用 |
| 缺 `Init.init(Context)` 调用点 | `JarLoader.load` 建完 DexClassLoader 就调 |
| `newCall` 返回**已执行的 `Response`** | 权威返回 `Call`，返回类型本身就是描述符的一部分 |

另外：`Spider` 默认返回 `""`（不是 `"{}"`）；`siteKey` 改 `@JvmField`；`SpiderApi` 必须是
**class 不是 interface**；`init` 只留 `(Context)`/`(Context,String)`（删掉自造的 `init(String)`）。

### 工具链：新增 `dex_probe.py`
真实 jar 是预编译的，**签名就是 ABI**。写了个真正的 DEX 解析器读 `method_ids`/`field_ids`，
再减去 jar 自身 `class_defs`，得到「这个 jar 向宿主索要什么」。踩坑三条：
- `dexdump` **不能 mmap Windows 上的 jar**，要先用 `zipfile` 抽出 `classes*.dex`
- 正则扫 dexdump 会因混淆类刷出 **4186 条假 field ref**
- `*_upgraded.jar` 的 `method_idx_diff` **不连续**，手写 `class_data_item` 解析必崩
  → 扫 `method_ids` 才可靠

### `build_mock_jar.py` 修了 3 个真 bug
1. `subprocess.run(text=True)` 用 UTF-8 解码 javac/d8 的 **GBK** 输出 → 先炸 `UnicodeDecodeError`，
   真错误看不见。
2. `fail("javac 失败\n" + r.stdout + r.stderr)` 里 `stdout`/`stderr` 可能是 `None` → `TypeError`。
   现在统一走一个 `run()` 助手：GBK 解码 + `or ""` 兜底 + 失败时把两路输出分块打全。
3. **第三方 jar 没进 classpath**：`Spider.client()` 返回 `okhttp3.OkHttpClient`，宿主 classes 里没有

   okhttp 4.12.0 + okio 3.6.0，同时喂 javac `-cp` 与 d8 `--lib`（**只作库、不 dex 进 jar**，
   否则 jar 里会再定义一份 `Spider`，`instanceof` 直接失败）。

### R8：两种破坏方式要分开堵
这里的关键认知是 —— **混淆和删除是 R8 的两件独立的事**，keep 规则管不了改名，
`-dontobfuscate` 也管不了删除：

| 手段 | 挡住的 |
|---|---|
| `-keep class com.github.catvod.** { *; }` | 成员**被删** —— 那些方法只给外部 jar 调，本 App 用不到，R8 眼里就是死代码 |
| `-dontobfuscate` | 名字**被改** —— jar 字节码里写死 `superclass = Lcom/github/catvod/crawler/Spider;` |

少任何一条，症状都是「编译过、装得上、只有那个站点被打开时才炸」。
关混淆对 MVP 几乎没有代价（本 App 没有要保护的 IP，也没有签名校验），
但把最致命的一整类风险直接消掉了。

另外 `-keepattributes Signature` 必须留：R8 默认删它，删了之后 Gson 拿不到泛型，
症状是「能请求、能返回、解析出来全是空对象」。

### `dex_probe.py` 修掉一个真 bug（顺带解释了老疑案）
`method_idx_diff` / `field_idx_diff` 是**组内**增量：DEX 把方法分成 direct 与 virtual、
字段分成 static 与 instance **两个各自独立排序的组**，每组第一条 diff 都相对 0。
原来跨组连续累加，第二组的 index 会飘到表外 → `struct.error: unpack_from requires a buffer of …`。

- **只在同时拥有两组的类上炸**，所以简单 jar 上一切正常
- 之前 `*_upgraded.jar` 解析失败被我判断成「那些 jar 格式特殊」—— **判断错了**，是解析器的错。
  这次在 R8 产物上再次触发才定位到根因。修法就是两组分别 `idx = 0`。
- 同一个 bug 在 `verify_release.py` 的字段解析里也有，一并修了（`siteKey` 一开始报"缺失"就是这么来的）。

### 虚惊一场：release 里找不到 `ic_launcher`

### 四个不能改的设计点（都是踩坑换来的）
1. **`saveProgress` 不是 `suspend`**，仓储自带 `CoroutineScope`。最关键的一次调用发生在
   界面正在销毁时，`scope.launch` 里那笔写入可能**一次都没开始就被取消** —— 症状是
   "退出时最后几秒没记住"，极难定位。
2. **`limitedParallelism(1)` 串行化写入**：并发写完成顺序不保证，极端情况下"较早的位置"
   后落盘，进度倒退。
3. **`ProgressWriteGate` 用可空 `lastAt`**：若用 `Long.MIN_VALUE` 表示"还没写过"，
   首次判断 `now - lastAt < window` **溢出成负数** → 判定"窗口内" → **第一次写入被吞**。
   时钟注入 → 纯 JVM 单测覆盖四条路径。
4. **`BeeDatabase` 刻意不写 `fallbackToDestructiveMigration()`**：参考项目开了它，效果是
   升级后无声清库。进度与收藏是用户攒的数据、不是缓存。

### 播放页的收尾顺序（错一步就丢进度）
- `onDispose`：**先 `saveNow(true)` 再 `release()`** —— release 后 `currentPosition` 归零
- 切集：**先落库再切**，切完读到的位置是新集的 0
- `PlaybackContext` 用 `rememberUpdatedState` 包起来（`DisposableEffect` 里的回调**只注册一次**，
  直接闭包捕获会永远存最初那一帧的空线路名 → 续播永远失效且不报错）

### 工具链：KSP × AGP 9 内置 Kotlin

## 导航崩溃修复：vodId 带 `/` 时 `navigate()` 直接崩（高城报的「点详情回桌面」）

### 根因（字节码级的，不是猜的）
`Routes.detail(vodId)` 把 vodId 原样插进路由：`"detail/糯米:/vod-detail-id-95012.html"`。
反编译 `navigation-common` 2.10.1 的 `NavDeepLink` 拿到两条硬事实：
- `PATH_REGEX = Regex("([^/]*?|)")` —— 占位符被编译成**排除斜杠**的捕获组，`/` 直接匹配失败
- 匹配成功后 path 参数会走 `NavUriUtils.decode` → 就是 `android.net.Uri.decode`
  （**不是** `URLDecoder`，所以 `+` 不会被吃成空格）
→ `IllegalArgumentException: Navigation destination that matches route … cannot be found`。
报错文案像"路由没注册"，其实路由好好的，是**值**把路径撑破了。

### 修法与反向陷阱
`Routes` 里 encode，读取端**绝对不要再 decode**（会双重解码，把原文里的 `%` 吃掉）。
```kotlin
fun detail(vodId: String) = "detail/${Uri.encode(vodId)}"
```
实测：`糯米` 源 → Hero 卡 / 海报卡两条路径进详情页正常；`player` 路由同样通。

## 播放失败的真实原因：没有本地代理服务（与兼容层无关）
logcat + 播放页 UI 都给出同一句：
```
java.net.MalformedURLException: invalid port: -1
http://127.0.0.1:-1/proxy?do=m3u8&url=https%3A%2F%2Fvip.123pan.cn%2F...
at com.github.catvod.spider.ProxyOrigin.Gc
```
jar 的 `ProxyOrigin` 会**逐个探测 9978、9979、9980…** 找宿主的本地代理，全拒；然后按
`Proxy.getPort()` 拼 URL，而宿主从没 `Proxy.set(port)` → 端口 -1。`/proxy` 就是待办里的
「本地代理服务」。**这一节不是 bug，是缺功能。**

## 宿主 ABI 到底缺什么 —— 用修好的 `probe_jar_symbols.py` 量出来
原脚本输出"字段 4186 / 方法 0"是**假数字**，两个 bug：
1. dexdump 的方法引用语法是 `名字:(参数)返回`，**名字后面有冒号**（`.init:(…)V`），
   写成 `.init(…)V` → 方法引用恒为 0。
2. **必须减掉 jar 自己定义的类**。jar 自带混淆过的内置 Jsoup（`com/github/catvod/spider/merge/*`），
   和站点类一起占了 500–900 个类，全在 `com/github/catvod/` 命名空间里。
   判据只能来自 `Class descriptor  : '…'` 那些定义行。
修完后三个真实 jar（XYQ / custom_spider / fty）的宿主需求 = **9 个成员**；
设备上在用的那个 jar 是 **11 个 `Spider` 成员 + 2 个 `SpiderDebug.log`**。
**全部已被现有 5 文件 / 560 行兼容壳覆盖 —— 兼容层不缺东西。**

## ⚠️ 静态探针有天花板：fty.jar 的真代码是 native 加密的
设备上 `files/catvod/jar/8432d174….jar` 的 **dex 只有 36 KB**，1.1 MB 里绝大部分是
`assets/ftyguard_v7.so` / `ftyguard_v8.so` / `ftyshinidie.guard`，运行时才解密。
所以 `ProxyOrigin` 静态**根本看不见**。→ 光靠 dexdump 量不完整，
**必须配合 logcat 运行时观察**（这就是这次找到端口 -1 的方式）。

真因在 `PlayerScreen.kt` 的 `MediaItem.fromUri(play.url)`：
`DefaultMediaSourceFactory` 不带 mime 时走 `Util.inferContentType(Uri)`，**只看 URI 最后一段路径**，
query 不参与。`http://127.0.0.1:9978/proxy?do=m3u8&url=…` 的最后一段是 `proxy` → OTHER
→ `ProgressiveMediaSource` → 就是上面那个报错。
**修法**：`player/MediaMime.kt` 的 `mimeTypeOfPlayUrl()` 显式给 MIME。判据两条，顺序不能换：
① 自指代理地址（路径 `/proxy` + query 里有 `do`）→ `do` 是唯一权威判据，**不往下落**；
② 直链 → 全串找 `.m3u8` / `.mpd`（含 query）。
⚠️ ①必须短路：`do=proxy`（取分片）的 `url=` 参数里照样带 `.m3u8`，百分号编码不动 `.`，
落到 ② 会被误判成 HLS。**这条是 `MediaMimeTest` 跑出来的，不是我推出来的**（第一版实现就是错的）。
`PlayerScreen` 另加 `BeePlayer` 起播日志（`mime=… url=…`），这次排查就缺它。
`LocalProxyServer` 加了成功路径日志，**按 `do` 去重只记第一条**（分片请求几十条会冲掉 logcat）。

### 其它真问题
- `DefaultHttpDataSource` 的 8s 默认连接/读超时**没改** → 源站慢一点直接判失败而非变慢。

# 缓存 / 流量 / 加载性能：按上面那份审计全部落地（2026-09-16 晚）

审计列了四个高收益项，**全部实现并装机实测通过**。下面按「改了什么 → 为什么 → 怎么验的」记。

## 1. 媒体磁盘缓存（`SimpleCache` + `CacheDataSource`）

新增 `player/MediaCache.kt`（进程内唯一 `SimpleCache` + LRU + `StandaloneDatabaseProvider`）
与 `player/PlayerFactory.kt`（LoadControl + DataSource 组装）。

### ⚠️ 两个**必须显式设**、而且反直觉的参数（反编译字节码查出来的）

`CacheDataSource.Factory` 的构造函数只给 `cacheReadDataSourceFactory`（FileDataSource）和
`cacheKeyFactory` 赋了值 —— **`cacheWriteDataSinkFactory` 是 `null`、`flags` 是 `0`**：

- **不设 `setCacheWriteDataSinkFactory`** → `CacheDataSource` 只读不写，「缓存开着」但磁盘上
  永远是空的，**而且不报任何错**。这是最阴的一种失败。
- **不设 `setFlags(FLAG_IGNORE_CACHE_ON_ERROR)`** → 缓存出问题（索引库损坏 / 磁盘写满 /
  分片读到一半断了）时异常**直接抛给播放器**，用户看到「这个源播不了」，真因是本地磁盘。
  带上这个 flag 才会弃用缓存、退回纯网络。**它在 media3 里不是默认值**，别想当然。

### 缓存放哪、为什么不释放重建
- 放 `externalCacheDir/media`：可再生数据，被系统清理掉可接受；放 `filesDir` 会被算进
  「App 数据」，用户看到占几个 G 却找不到地方清。
- **配额在同一次运行里被改过时不重建**：重建要 `release()` 旧实例，而此刻可能有播放器
  正握着它读 → use-after-release，崩溃点在 media3 内部、栈里看不出跟设置有关。
  新配额下次冷启动生效，日志里有交代。
- **清空缓存**（`release()` + `SimpleCache.delete`）确实能在同一进程内重建，实测过：
  清完再播，日志出现 `媒体缓存就绪…构建耗时 12ms`，没有
  `Another SimpleCache instance uses the folder`。这一条**必须实测** —— 上面的
  `runCatching` 会把「目录锁没解开」静默降级成「不缓存」，看起来像功能没生效。

### 构建要挪到后台（实测 92ms）
`SimpleCache` 构造要碰文件系统（加目录锁）和索引库。播放页那个 `remember { }` 是**在组合期、
主线程上**跑的 → 92ms 直接就是用户点开一集时的一次掉帧。
`BeeApplication.onCreate` 里 `MediaCacheProvider.warmUp()` 起后台线程先建，`get()` 语义不变
（没建就现场建），预热只是让常见路径快一点，不是给调用方加新义务。

## 2. `detail` / `playTarget` 请求合并窗口

抽出 `data/repository/MergeWindow.kt`（原先是 `home()` 里的一坨，现在三处共用）。
- **时钟做成注入参数**（`clock: () -> Long`）：默认 `SystemClock.elapsedRealtime()`，但纯 JVM
  测试里那是 android.jar 的**桩、恒返回 0**，「窗口过期」这条分支**永远测不到**。注入之后
  6 个用例全覆盖（含边界 999 命中 / 1000 出窗、在途并发合并、失败不写快照）。
- key：首页带 `activeSourceId`（`selectSource()` 不作废窗口，不编进 key 就会看到上一个源的首页）；
  `detail`/`playTarget` 用 vodId 就够（`vodId = siteKey:sourceId`，跨源天然不撞）。
- `playTarget` 窗口**故意也短**：jar 源常给带签名、有时效的地址，缓存越久越可能拿过期地址去播，
  那种失败表现是「这一集播不了」、重试一次就好，极难排查。

## 3. `DefaultLoadControl`（缓冲策略）

默认值是「至少 50s / 最多 50s / 2.5s 起播 / 回退缓冲 0s」，四个数字各有一个问题：
| 改成 | 为什么 |
|---|---|
| 起播门槛 2500 → **1500ms** | 源站首包慢时用户对着转圈干等 |
| 前向缓冲 50 → **30s** | 50s×771KB/s ≈ **38MB**，看 30 秒就退出的话大半白下 |
| 回退缓冲 0 → **15s**（从关键帧） | 默认往回拖 10 秒就要重新走一遍网络 |
| `targetBufferBytes` → **64MB** | 默认按可用内存算，8G 机器能到 80MB+ |

⚠️ 有磁盘缓存之后，多缓冲的那部分**不再是纯浪费**（留在磁盘上，下次看还省流量），
所以前向缓冲没取更激进的值。

## 4. 播放器不再跟着 `headers` 重建

`remember(headers)` 连播放器一起换的写法有真 bug：切集瞬间 `target` 短暂为 null →
`headers` 变空 map → **播放器整个重建**；真 headers 到了又重建一次 → 一次切集建两个播放器、
解码器白初始化两遍。现在：播放器 `remember {}` 只建一次，**媒体源**才是跟着 headers 走的那层。

## 5. 配置 JSON 离线副本

新增 `data/local/ConfigDiskCache.kt`。配置地址是唯一入口，拉不到就只剩设置页，而它偏偏挂在
GitHub Pages / 小站后台这类最容易失败的地方。只在**网络失败**时回落到同一地址的上次成功副本，
正常情况永远用最新的一份（不是 TTL 缓存）。状态里标出「（离线副本）」。
写入顺序**先正文后地址**：中途被杀时地址要么缺失要么还是旧的 → 判为不可用，退化成「没有副本」；
反过来写会出现「地址是新的、正文是旧的」= 静默拿旧配置当新配置用。

## 6. 顺带修的两处
- 播放器的 `DefaultHttpDataSource` 现在**必带 UA**：来源给了就用它的，没给补
  `CatVodHttp.DEFAULT_UA`（为此把它从 private 改成 public）。站点接口和媒体分片打的是同一批
  CDN，UA 不一致就是「详情页能开、一播就 403」。ExoPlayer 自带的 `ExoPlayerLib/x.y.z` 更容易被拦。
- `MediaSourceFactory` 在 media3 1.11.1 **已废弃**，改用 `MediaSource.Factory`（编译告警会指出来）。
