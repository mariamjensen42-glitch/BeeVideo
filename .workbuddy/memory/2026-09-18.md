## CI/CD：GitHub Actions 工作流

高城要求「分析架构 + 写 workflow 实现自动构建/测试/部署」。三个决策点先问了他，
全部按推荐项：**部署到 GitHub Release** / **不跑仪器测试** / **CI 用正式签名密钥**。

新增：
- `.github/workflows/ci.yml` —— push + PR：单测 → debug+release 构建 → R8 差分校验。
  用 find 而不是写死文件名（未签名时产物叫 `app-release-unsigned.apk`）。
- `.github/workflows/release.yml` —— tag `v*`：签名构建 → apksigner 验签 → 差分 →
  GitHub Release + SHA256SUMS。`workflow_dispatch` 是**演练模式**（构建校验全跑，不建 Release）。
- `.workbuddy/scripts/lint_workflows.py` —— 本地校验 workflow：YAML 结构 + 把每个 run 块
  抠出来喂 `bash -n`（YAML 合法 ≠ 流水线能跑）。
- `app/build.gradle.kts` 支持 `-Pbeevideo.versionName` / `-Pbeevideo.versionCode`（不传＝原值）。

改动理由的关键一条：**R8 差分校验不需要签名密钥** —— R8 的删减与签名无关，未签名 release
APK 接口面完整，照样能差分。所以把它放进 CI（每次 push/PR）而不是发布流水线，让
「proguard 规则被误删」这种事在 PR 上就变红，而不是等发版才炸。

修：
- `verify_release.py` §3 的探测项 `JarSiteClient` **源码里已不存在**（现名 `SpiderSiteClient`）
  → 修掉。它不影响退出码，但会在每份 CI 日志里挂一个假红叉，纯噪音。
- `git update-index --chmod=+x gradlew`：仓库里是 **100644**，没有执行位。

## 上线 GitHub 并发布 v1.0.0（同日稍后）

**仓库：https://github.com/mariamjensen42-glitch/BeeVideo （公开 + GPL-3.0）**

### 三个决策（都问过高城）
1. **公开 + GPL-3.0** —— JS 引擎是 FongMi/TV（GPL-3.0）的逐行翻译，公开即分发，
   必须整体以 GPL-3.0 发布。`LICENSE` 从 GitHub licenses API 取全文（35149 字节）。
2. **第三方 JS 运行库不进版本库**（cat.js / cheerio.min.js / crypto-js.js / gbk.js

   **拉不到即 fail**。⚠️ 缺它们的包构建时**不报错**、体积只小 317 KB —— 极易漏掉。
3. **排除 `release-real-source-*.png`**（图里有真实站点名「神秘的哥哥们」+ 海报上的
   引流二维码 = 变相推荐内容源），并**重写全历史**清除：`git filter-branch --index-filter`
   + 删 `refs/original` + `reflog expire --expire=now` + `gc --prune=now`。
   四个 commit 的 hash 全部变过（旧历史仅存在于本地，仓库刚建、无人受影响）。

### 踩的坑（全部已修）
- ⚠️ **CI 第一次红在 R8 差分上**，真因是 `verify_release.py` §4 把「未签名」判为失败，
  而公开仓库的 PR 流水线**不该**拿签名密钥 → CI 产出的包必然未签名。
  **这是我设计上的自相矛盾**：一边论证"差分不需要签名"，一边让脚本强制要求签名。
  → 加 `--allow-unsigned`，**只给 CI 用**；发布流水线不传（那里签名是硬要求）。
  教训：这种"与本次改动无关的常驻红"会训练人忽略整个 job，比不跑还糟。
- ⚠️ **`tags: ['v*']` 会误触发发布**：`vendor-js-v1` 也以 v 开头 → 改 `v[0-9]*`。
- ⚠️ `git commit --amend` 会把**当前已暂存**的东西一起吞进去 → 拆 commit 时先
  `reset --soft HEAD~1`。
- ⚠️ 两个 heredoc 挤在一条命令里，第一个会把后面的内容全吃进自己的 message
  → 改 `git commit -F <文件>`。
- ⚠️ `git push` 会撞上 `git config` 里写死的 `http.proxy=127.0.0.1:10809`（常是死的，
  报 502 / tunnel failed）；活代理在环境变量 `http_proxy` 里
  → `git -c http.proxy=$http_proxy -c https.proxy=$http_proxy push`。
  （`gh` 命令走自己的通道，不受这个配置影响，所以 gh 一直好用。）
