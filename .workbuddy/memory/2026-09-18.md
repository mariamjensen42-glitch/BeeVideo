## CI/CD：GitHub Actions 工作流

高城要求「分析架构 + 写 workflow 实现自动构建/测试/部署」。三个决策点先问了他，
全部按推荐项：**部署到 GitHub Release** / **不跑仪器测试** / **CI 用正式签名密钥**。

新增：
- `.github/workflows/ci.yml` —— push + PR：单测 → debug+release 构建 → R8 差分校验。
  用 find 而不是写死文件名（未签名时产物叫 `app-release-unsigned.apk`）。
- `.github/workflows/release.yml` —— tag `v*`：签名构建 → apksigner 验签 → 差分 →
  GitHub Release + SHA256SUMS。`workflow_dispatch` 是**演练模式**（构建校验全跑，不建 Release）。
- `.workbuddy/scripts/lint_workflows.py` —— 本地校验 workflow：YAML 结构 + 把每个 run 块
  抠出来喂 `bash -n`（YAML 合法 ≠ 流水线能跑）。
- `app/build.gradle.kts` 支持 `-Pbeevideo.versionName` / `-Pbeevideo.versionCode`（不传＝原值）。

改动理由的关键一条：**R8 差分校验不需要签名密钥** —— R8 的删减与签名无关，未签名 release
APK 接口面完整，照样能差分。所以把它放进 CI（每次 push/PR）而不是发布流水线，让
「proguard 规则被误删」这种事在 PR 上就变红，而不是等发版才炸。

修：
- `verify_release.py` §3 的探测项 `JarSiteClient` **源码里已不存在**（现名 `SpiderSiteClient`）
  → 修掉。它不影响退出码，但会在每份 CI 日志里挂一个假红叉，纯噪音。
- `git update-index --chmod=+x gradlew`：仓库里是 **100644**，没有执行位。

实测（本机，都用 debug 环境的 gradle 通道）：
- workflow YAML + 内嵌 shell 全绿；校验器**自检过**（故意写坏的脚本确实被抓出来，好脚本不误报）
- `-Pbeevideo.versionName=9.9.9 -Pbeevideo.versionCode=90909` → aapt2 确认
  `versionCode='90909' versionName='9.9.9'`，注入生效
- 单测 **204 用例 / 0 失败 / 0 跳过**（⚠️ 记忆里的「148 全绿」是旧数，以 204 为准）
- `assembleDebug + assembleRelease` 3m40s，`verify_release.py` **EXIT=0，全项通过**
- release 11,335,634 vs debug 82,167,087 字节，压掉 86.2%

`gh repo create ... --source=. --push` + 配 4 个 secrets
（`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` / `KEY_PASSWORD` / `KEY_ALIAS`）。
