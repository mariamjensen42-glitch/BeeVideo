## 功能缺口审查（高城问「缺什么必要功能」）

对照 `docs/scope-and-m1-delivery.md` §2.1/§6.1/§6.3 逐条核代码，**文档承诺但零实现**的欠账：

| 缺口 | 证据 |
|---|---|
| 本地媒体（SAF） | `data/source/local/` 只有 `.gitkeep`；Manifest 无 `OpenDocument`。§6.3 验收 1 无法达成 |
| 网络直链 + 系统分享接管 | `data/source/direct/` 只有 `.gitkeep`；Manifest **无 `ACTION_VIEW`/`ACTION_SEND` intent-filter**。§6.3 验收 3 无法达成 |
| 解码器偏好（硬/软解） | 全仓无 `MediaCodecSelector`（§6.1 第 11 项 ❌） |
| 自定义请求头 UI+持久化 | 只有引擎层 `PlayTarget.headers`（§6.1 第 12 项 ⚠️） |
| 搜索历史 / 热词 | `searchHistory` 零命中 |
| 类型筛选（站点 `filter` 参数） | 数据层不解析，UI 无筛选行（`HomeFeed` 的"筛选行"实为分类 chips） |
| 多源并存 / 排序 / 单站启停 | 设置只有单地址 + 5 条预置 + 清除；`SourcePickerSheet` 只有搜索选择 |
| 首启免责声明 | 只有【关于】里静态文本，无首启强制展示（§2.3 合规要求） |

**⚠️ 本次最硬的技术发现：`BeeChipGrid` 上挂长按**
两条直觉路全断：
1. `Modifier.combinedClickable` 挂 chip 外层 → 收不到，因为 `ToggleButton` 内部的 `selectable`
   在 **Main pass 消费**，而 Main pass 是**子节点优先**。
2. `onCheckedChange = null` 让它退化成纯视觉 → **material3 1.5.0-alpha28 里这个参数不可空**，
   编译期 `Argument type mismatch: actual type is 'Nothing?'`。

也试过把 `detectTapGestures(onLongPress=…)` 挂 chip 的 label（在 content 里 = 子节点，Main pass 拿得到）
→ 它消费 down，`ToggleButton` 的点击随即失效。

**最终解**：`Modifier.observeLongPress` —— 只在 **Initial pass**（父到子、事件未被消费）观察，
**一个事件都不消费**。chip 的点击/水波纹/选中态全不受影响。读屏语义靠
`Modifier.semantics { onLongClick(label=…) }` 另补（观察不产生语义）。

**另两条 UML 级的坑（已写进 ADR-0011）**
- `Card` 的 content 是 `@Composable ColumnScope.() -> Unit`，抽出来的 `() -> Unit` 传不进去。
- `Modifier.combinedClickable` 带 `indication` 的重载**要求 `interactionSource` 也在**，
  只给 `indication` 报"没有适用候选"。

**验证**：`:app:compileDebugKotlin` 通过、`:app:testDebugUnitTest` 全绿、`:app:assembleDebug` 出包。
⚠️ **没上真机**（`adb devices` 一台都没连）—— 尤其是长按手势在 `ToggleButton` 上是否稳定触发。
