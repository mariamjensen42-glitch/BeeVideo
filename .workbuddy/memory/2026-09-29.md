## 修 Bug：播放页有声音没画面、控件全哑（ADR-0012 引入）

**症状**：进播放页 UI 正常，画面全黑；`dumpsys media_session` 却显示 `state=PLAYING`+位置在走，
logcat 里 `c2.android.avc.decoder` 正常建、SurfaceFlinger 也报了 `videoDecoderInfo->state=1`
—— 声音与解码都对，只有画面没有；顺带进度条永远 `00:00`、暂停/拖动/倍速全无反应、进度不落库。

**真因**：`PlaybackService.Callback.onConnect` 用了 `AcceptedResultBuilder()` **无参构造**，
而它给的是 `SessionCommands.EMPTY` / `Player.Commands.EMPTY`（不是默认集）；
我们只 `.setAvailableSessionCommands(...)` 覆盖了前者，**player 命令一条都没有**。
`setVideoSurface` / `getCurrentPosition` / `play` / `seekTo` 全是 player 命令，
media3 对未授权命令**静默丢弃**（不抛不报）→ 只有一组无日志可查的症状。
（`javap -p -c` 打无参构造确认；`DEFAULT_PLAYER_COMMANDS` = `addAllCommands()`。）

**改**：`PlaybackService.kt` 加一行 `.setAvailablePlayerCommands(DEFAULT_PLAYER_COMMANDS)`。

**验证（真机 M2104K10AC，debug）**：画面出、进度条 `00:24 / 10:00` + `1.0x` 正常、
点暂停 → `state=2` 且位置冻结、返回后历史表写入 `positionMs=368751 / durationMs=600600`。
`assembleDebug` 通过、单测全绿。

**顺带修掉（高城指定）**：`PlaybackCoordinator.attach` 对同一 `vodId` 复用旧持有者、
**路由带的 lineIndex/episodeIndex 被忽略** —— 看完第 3 集返回、进详情点「第05集」还是接着放第 3 集
（重构前路由参数每次进页面都生效）。方案：持有者加 `applyRoute(lineIndex, episodeIndex)`，
**只认"和当前不一样"**（重进同一页不能把正在放的重来一遍），先落旧进度再改号、越界当场夹。

⚠️ 两条落点约束：
- **必须在 `LaunchedEffect` 里调**：`applyRoute` 会落库，放在组合期等于每次重组写一次库。
- `PlayerScreen` 的 `LaunchedEffect(vod, lineIndex, episodeIndex)` 里 **`vod == null` 时不 bind**
  （`vod?.let(state::bind)`）—— 复用中的持有者正被播着，把快照抹成 null 会让那一下的落库
  写进一条空片名。
- 顺序：**applyRoute 在 ensurePlaying 之前**，否则先起播会闪一下上一集。

**真机验证**：首页继续观看（第04集）→ 播放 → 返回 → 历史长按「查看详情」→ 详情页点「第05集」
→ 新的起播日志 + 会话元数据 `线路1 · 第05集` + 页面高亮 chip `05`；
再回首页点「继续观看（第05集）」→ **起播日志条数不变**（空操作没被破坏）。
单测 352 → **357**（+5 条 `applyRoute`），全绿。assembleDebug 出包。

## 退出播放页改成画中画小窗（高城拍板，取代 ADR-0012 的「离开页面音频继续」）

**原症状**：退出播放页后音频继续、屏幕上什么都没有，通知栏虽有但用户不认这个。
高城拍板：**退出播放页 → 系统画中画小窗**；「返回键/导航离开」才算离开（按 Home 仍继续放）。

**新增**
- `ui/player/PlayerPip.kt` — `isSupported` / `params(autoEnter)` / **纯函数 `shouldEnterPip(state, supported)`**（可 JVM 直测）
- `app/src/test/.../PlayerPipTest.kt`

**改**
- Manifest：`supportsPictureInPicture="true"` + configChanges 加 `smallestScreenSize`（不加会因进出小窗重建 Activity）
- `MainActivity`：`inPip` 状态 + 关小窗的收场判定；`BeeNavHost` 与 `PlayerScreen` 透传 `inPipMode`
- `PlaybackSession`(+`pause()`)/`MediaControllerPlaybackSession`/`FakePlaybackSession`；
  `PlayerPlaybackState.pauseAndSave()`；`PlaybackCoordinator.pauseForExit()`

**三条硬规则（每条都踩过一次）**
1. **进小窗不退栈**（展开要回播放页）→ 所以判据 `shouldEnterPip` **只认 Playing/Buffering**。
   一开始写的是"非 Idle 非 Failed"，于是**暂停态按返回也进小窗** → 用户被锁死：按返回是小窗、
   关掉小窗 App 退到后台、从桌面点回来还是播放页，**回不去列表**。暂停态退栈就是唯一的退出口。
2. **关小窗的判定不能靠回调先后**：`onStop` 与 `onPictureInPictureModeChanged(false)` 谁先谁后
   系统没保证（实测关掉小窗时**任务还在**，Activity 只是被移到后台，所以 `onTaskRemoved` 也不可靠）。
   最终：回调只置标记，`onStop` 里 `postDelayed(300)` 后看 `lifecycle.currentState == CREATED`；
   `onStart` 清标记（展开会回前台）。三条缺一条就误停或漏停。
3. **单 Activity → PiP 缩的是整窗**：`inPipMode` 时播放页只画画面。
   实现上**复用 `PlayerScaffold`**（`isFullscreen = isLandscape || inPipMode`）+ 不画 overlay，
   这样 AndroidView/`SurfaceView` 不重建 —— 与「全屏与竖屏共用一棵树」同一个理由。
- `autoEnterEnabled`（API 31+，minSdk 31 不用分支）**跟返回键同一条判据**：暂停态按 Home 也不冒小窗。

**真机验证（M2104K10AC / debug，全部 ✓）**
| 场景 | 结果 |
|---|---|
| 在播 + 返回键 | 进小窗（`mLastReportedPictureInPictureMode=true`），**小窗里只有画面**（无顶栏/选集） |
| 小窗展开 | 回播放页，仍在播（位置 122262 → 135992 继续走） |
| 小窗关闭 | `state=2` 暂停，位置冻结（122256 不动） |
| 暂停态 + 返回键 | **退栈回首页**（看到「继续观看 第07集」），没进小窗 |
| 在播 + Home | 进小窗，继续播 |
| 暂停 + Home / 首页 + Home | 都不进小窗 |

单测 357 → **362**（+`PlayerPipTest` 4 条，+`pauseAndSave` 1 条，全绿）。assembleDebug 出包。

**⚠️ 遗留**：在播时按返回进小窗、不退栈，所以**正在播时没法回列表页**（得先暂停或关掉小窗）。
高城要的是"小窗"，这是 PiP 的固有语义（PiP = 退到后台但可见）；若他想"边看列表边听"，
那对应的是**应用内迷你播放条**（当时 Q1 的第三选项），要另做。
另外**从最近任务划掉**现在仍会继续放（通知栏可控），没动 `onTaskRemoved`。

## 画中画开关收回"返回"那条路（高城四轮）

高城反馈：**「画中画，设置[里]关了，但是还在啊」** —— 关掉开关后退出播放页，小窗照旧出现。

**根因是我上一轮改过头了**：他上一轮说的"不该返回桌面"我只改了"返回去哪"（改成进应用内小窗），
却把小窗做成了**无条件**出现，开关挪去只管按 Home。而他的模型从二轮起就是那句
「一般情况是退出播放页面就停止播放的，除非开了画中画」—— **开关管的就是"退出播放页要不要继续放"**。

**现在的口径（开关 = 退出播放页要不要继续放）**
| 开关 | 返回键 | 按 Home / 切 App |
|---|---|---|
| **关（默认）** | 退栈回上一页 + 落进度 + **暂停**，无小窗 | 退到后台，声音继续（通知栏可控） |
| 开 | 退栈回上一页 + **应用内小窗**继续放 | 缩成**系统小窗** |

两种情况下返回都**不会**退到手机桌面。

**改**
- `PlaybackSettings.pictureInPicture`：`var` → **`val StateFlow<Boolean>` + `setPictureInPicture()`**
  （⚠️ **本项是唯一做成 Flow 的**：别项的改动等"下次起播/下次进页面"读就行，只有它必须**当场**生效 ——
  播放页与小窗都挂着"退到后台自动进系统小窗"的开关，设置页拨完不重新进页面也得跟着变）
- `PrefsPlaybackSettings` / `FakePlaybackSettings` 跟着改；`SettingsScreen` 这一项**不再用本页 `remember`**
- `PlayerScreen.leavePlayer`：`if (pipEnabled) showMiniPlayer() else { hideMiniPlayer(); pauseAndSave() }`
- `BeeNavHost`：小窗显示条件加 `pipEnabled`（开关关着时**绝不**有小窗）；
  新增 `LaunchedEffect(pipEnabled) { if (!pipEnabled) pauseForExit() }`
  —— 小窗正放着时关掉开关，窗口会消失但**播放不会自己停**，不补这一下就是"画面没了、声音还在响"
- 设置页说明文案重写（写明"两种情况下返回都不会退到手机桌面"）

**真机验证（M2104K10AC / debug，全部 ✓）**
① 开关关（默认）+ 播放中按返回 → `state=2` 暂停、小窗节点数 0、不进系统 PiP；
② 开关开 + 播放中按返回 → `state=3` 继续播 + 小窗在（`关闭小窗` 节点可见）；
③ **小窗正放着时**在设置页关掉开关 → 当场 `state=2` 暂停 + 小窗消失。
单测 **362** 全绿，assembleDebug 出包。测试机开关已复位为默认关。
